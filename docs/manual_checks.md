# 수동 확인 절차 (모의투자)

자동 테스트로 확인할 수 없는 것들을 **사용자가 직접** 확인하는 절차입니다.
모의투자(`IS_MOCK_TRADING=true`)에서만 하세요. 실전에서는 하지 마세요.

- 봇이 만든 주문·포지션이 KIS 앱의 실제 내역과 일치하는가
- 체결 확인·미체결 취소가 실제로 동작하는가

---

## 0. 준비

```bash
grep "🔒 현재 모드" logs/bot.log | tail -1     # "모의" 인지 반드시 확인
```

`실전`으로 찍혀 있으면 **여기서 멈추고** `IS_MOCK_TRADING=true` 로 고치세요.

`data/bot.db` 를 백업해 두면 확인 후 되돌리기 쉽습니다.

```bash
cp data/bot.db data/bot.db.bak.$(date +%Y%m%d%H%M%S)
```

---

## 1. 매수 체결 후: 체결 조회 결과 ↔ KIS 앱 주문 내역 일치 확인

**전제**: 주문번호 필드(`broker_order_no`)가 아직 확인되지 않아(T04 기준)
체결 조회가 구현되지 않았습니다. 이 절차는 **그 필드가 채워진 뒤**(T05) 실행하세요.
그 전에는 "1-3" 만 확인하면 됩니다.

1. 봇을 실행해 매수 주문이 나가게 합니다.
2. 로그에서 주문을 찾습니다.
   ```bash
   grep "주문기록\|매수 주문 접수\|체결" logs/bot.log | tail -20
   ```
3. DB 의 주문 기록과 KIS 앱(주문 내역)을 나란히 놓고 비교합니다.
   ```bash
   .venv/bin/python -c "
   import db
   c = db.open_db()
   for o in db.list_orders(c, limit=5):
       print(o['id'], o['symbol'], o['side'], o['qty'], o['price'], o['status'],
             o['filled_qty'], o['avg_fill_price'], o['broker_order_no'])
   c.close()"
   ```
   확인 항목:
   - [ ] 주문 수량·가격이 KIS 앱과 같다
   - [ ] `status` 가 실제 상태(접수/체결/취소)와 맞다
   - [ ] `filled_qty` 가 KIS 앱의 체결 수량과 같다 (부분 체결이면 그 수량)
   - [ ] `avg_fill_price` 가 KIS 앱의 평균 체결 단가와 같다

4. **불일치를 찾으면** 보고하세요. 체결가·수량이 다르면 응답 필드 매핑이 틀린 것입니다.

## 2. `get_all_holdings()` 응답 ↔ 실제 보유 일치 확인

대조(`reconcile`)의 정확도가 여기에 달려 있습니다. 이게 틀리면 봇이 외부 보유로 오판합니다.

```bash
# 국내
.venv/bin/python -c "import kis_domestic as kd; print(kd.get_all_holdings())"
# 해외
.venv/bin/python -c "import kis_overseas as kis; print(kis.get_all_holdings())"
```

KIS 앱의 보유 종목 화면과 비교하세요.

- [ ] 종목코드가 같다 (`symbol`)
- [ ] 수량이 같다 (`qty`)
- [ ] 평균 단가가 같다 (`avg_price`)
- [ ] **보유가 아닌 종목이 섞여 있지 않다** (수량 0 행이 들어오면 대조가 깨집니다)
- [ ] 보유 종목이 하나도 없으면 빈 리스트(`[]`)가 나온다

`reconcile` 이 매 사이클 도는데, 이 응답이 틀리면 `🚨 신규 매매 중단` 로그가 반복됩니다.
그 로그가 보이면 **봇을 멈추고** 위 두 응답을 먼저 확인하세요.

## 3. 미체결 주문이 취소되는지 확인

지정가를 현재가에서 멀리 떨어뜨리면 체결되지 않습니다.

1. `.env` 에 `ORDER_TIMEOUT_MINUTES=1` 을 넣습니다(기본 30분 → 1분).
2. **모의투자에서만** 봇을 실행해 매수 조건을 만족시킵니다.
   `ORDER_PRICE_TICKS` 를 음수로 두면 매수 지정가가 낮아져 미체결되기 쉽습니다.
   (`ORDER_PRICE_TICKS=0` 이면 현재가 그대로 → 체결될 수 있습니다.)
3. 로그를 봅니다.
   ```bash
   grep "미체결 취소\|미확정(UNKNOWN)\|주문번호를 얻지 못했습니다" logs/bot.log
   ```
4. KIS 앱 주문 내역에서 해당 주문이 **취소**로 바뀌었는지 확인합니다.

- [ ] 취소가 실제로 일어났다
- [ ] DB 주문 상태가 `CANCELED` 다
- [ ] 부분 체결분은 취소되지 않고 포지션에 남아 있다

**주의**: 주문번호 필드가 확인되기 전에는 4번(취소 호출)이 동작하지 않습니다.
그때는 `[reconcile] 주문 #.. 이 ...분을 넘겼습니다` ERROR 로그만 남습니다 —
이 로그가 나오면 수동으로 KIS 앱에서 취소하세요.

## 4. 타임아웃 시 재시도하지 않는지 확인

네트워크를 끊고 주문 사이클을 돌리면 됩니다.

1. 봇 실행 중 Wi-Fi 를 끕니다(또는 케이블 분리).
2. 매수 조건이 되는 시점까지 기다립니다.
3. 로그 확인:
   ```bash
   grep "결과 미확정\|재시도하지 않습니다\|UNKNOWN" logs/bot.log
   ```
4. KIS 앱 주문 내역에서 **같은 주문이 2건 이상** 나가지 않았는지 확인합니다.

- [ ] 주문이 한 번만 나갔다 (재시도로 중복되지 않음)
- [ ] DB 에 `UNKNOWN` 상태 주문이 1건 있다
- [ ] 그 다음 사이클에서 같은 종목 신규 주문이 `중복 주문 차단` 으로 막혔다

```bash
cp data/bot.db.bak.<타임스탬프> data/bot.db
```
